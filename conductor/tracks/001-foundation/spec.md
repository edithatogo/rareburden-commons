# Track 001 specification — Foundation and public-data protocol

## Objective

Create a reviewable, version-controlled foundation for RareBurden Commons using the Conductor context-driven development pattern.

## Required outputs

- persistent product, technical and workflow context;
- vision, mission, purpose and strategy;
- MoSCoW requirements baseline;
- Mermaid system and governance design;
- a public-data-first rare-disease burden protocol;
- a machine-readable data-source register with validation;
- Git history comprising logical, reviewable commits.

## Acceptance criteria

1. A new contributor can understand the programme and first deliverable from repository documentation alone.
2. Requirements separate the first public-data release from later controlled-data capabilities.
3. Architecture explicitly prevents central collection of sensitive records by default.
4. The protocol defines estimands, inclusion rules, provenance, uncertainty and double-counting controls.
5. The initial source register passes automated schema validation.
6. Tests run without network access.
7. No patient-level data or credentials are present.

## Out of scope

- downloading complete third-party datasets;
- applying for controlled access;
- producing a numerical global burden estimate;
- representing any organisation as a confirmed partner.
