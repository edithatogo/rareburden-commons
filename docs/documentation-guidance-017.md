# Documentation quality, accessibility and correction guidance

Documentation should use plain language, descriptive headings, meaningful link
text, fenced commands with expected outcomes, and no colour-only distinction.
Tables must have a header row; examples must identify whether they are
observed, transformed, modelled or assumed. Keep command output optional and
avoid requiring a specific screen size or assistive technology.

Citation and licensing must identify the source, release/version, retrieval
event, terms and transformation. Code and original documentation licences are
described in the repository licence files; third-party data retain their own
terms.

To request a correction or report an accessibility or harm issue, open a
public issue with the versioned artefact identifier and a minimal description.
Do not include personal, row-level, small-cell or controlled data. Maintainers
must preserve the original record, document the correction and link a
superseding version rather than rewriting history. Scope, patient/community,
data-governance and release decisions remain accountable gates.
