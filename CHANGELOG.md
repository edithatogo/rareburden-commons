# Changelog

All notable changes will be documented here. The project uses semantic versioning for software and independent version identifiers for protocols, schemas, source releases and analytic releases.

## [0.3.0rc2] — 2026-07-27

### Added

- Fail-closed acquisition, local-release registration and immutable source provenance.
- Four synthetic/offline source normalisers and common scientific record contracts.
- Semantic hierarchy, ontology mapping and overlap-safe aggregation primitives.
- Evidence/parameter ledger, quality and transportability gates, uncertainty decomposition and reproducible modelling.
- Synthetic public-data gap map and adjacent-initiative landscape register.
- Prospective protocol registration, decision/deviation logs and activity-level transformation provenance.
- Closed workflow lineage, W3C PROV-O, RO-Crate/Process Run Crate, GATHER evidence and conservative reproducibility levels.
- Independent seven-gate verifier that reconstructs calculations and scholarly assurance from packaged bytes.
- Runtime-asset projection, package inspection, SBOM, locked-requirements and reproducibility harnesses.
- Hardened GitHub Actions designs for CI, CodeQL, dependency review/audit, Scorecard and attested releases.

### Changed

- Package and scholarly metadata are reconciled at `0.3.0rc2`.
- Workflow entry-input projection is deterministic even when one artefact serves different analytical roles.
- Release manifests can record repository identity separately from the release-object directory.
- GATHER verification now supports non-empty evidence directories as well as regular files.
- The synthetic assurance object includes an inspectable source tree and deterministic source snapshot archive.

### Verified in the handoff environment

- Programme, catalogue, roadmap, landscape and JSON Schema validation.
- End-to-end synthetic reference generation.
- Independent verification of all seven release-assurance gates.
- Core test suite excluding the Hypothesis-only module where that dependency was unavailable.

### Remaining release gates

- Install and execute the exact locked development environment and full property-based/type/lint suite.
- Complete live source, terms and redistribution verification.
- Complete external novelty challenge, patient/community review and data-governance review.
- Prove hosted GitHub security/attestation workflows.
- Complete an independent reproduction before claiming R3.
- Do not issue final v0.3.0 until Tracks 002 and 007 pass their external gates.

## [0.2.0] — 2026-07-19

### Added

- Gate-based roadmap from the foundation through stable v1.0.0.
- Complete 17-track Conductor portfolio with specifications, plans, metadata, dependencies, owners, review gates and target releases.
- Machine-readable roadmap and track-metadata JSON Schemas.
- Offline roadmap, dependency, release-assignment and track-integrity validation.
- Maturity model and blocking multi-domain v1 acceptance contract.
- Requirements traceability, testing strategy, release policy and programme risk register.
- Mermaid delivery, assurance, lifecycle and release-evidence designs.
- Formal reviews for the foundation and v1-delivery-system tracks.
- Python 3.11–3.13 continuous-integration matrix and dependency update configuration.

### Changed

- `make check` now validates the complete programme and includes linting.
- Repository safety scanning now works in both Git clones and clean source archives.
- Product, strategy, architecture and workflow documents now distinguish planned capabilities from implementation evidence.
- Package version advanced to 0.2.0 and supported Python floor lowered to 3.11.

### Known limitations

- Public-source acquisition adapters, semantic mappings, parameter ledger, burden engine, demonstrators and federated node runner are not yet implemented.
- Governance bodies and external partnerships remain proposed rather than constituted.
- No burden estimate is published by this release.
